# StreamFlow – Video Streaming Buffer Management System

A Java-based Operating Systems mini-project that simulates multimedia streaming using the **Producer–Consumer problem**, a shared buffer, multithreading, and synchronization.

## 📌 Project Overview

StreamFlow demonstrates how media chunks are generated by a streaming server, temporarily stored in a shared buffer, and consumed by user devices.

The project uses a bounded FIFO queue to manage media chunks. When the buffer is full, the producer waits for free space. When the buffer is empty, the consumer waits for new chunks.

A Java Swing graphical user interface allows users to configure the simulation and monitor its performance.

## 🎯 Objectives

- Understand the Producer–Consumer problem in Operating Systems.
- Implement multithreading using Java.
- Manage shared resources using synchronization.
- Handle full-buffer and empty-buffer conditions.
- Demonstrate inter-thread communication using `wait()` and `notifyAll()`.
- Monitor buffer usage and producer-consumer activity through a graphical interface.

## ✨ Features

- **Configurable Buffer Capacity:** Set the maximum number of chunks the buffer can store.
- **Configurable Media Chunks:** Specify the total number of chunks to produce.
- **Media Type Selection:** Simulate video or audio chunks.
- **Production Delay:** Configure the time between chunk production.
- **Playback Delay:** Configure the time taken to consume chunks.
- **Multiple User Devices:** Configure the number of consumer devices.
- **Producer–Consumer Synchronization:** Coordinate access to the shared buffer.
- **Buffer Full Handling:** The producer waits when the buffer reaches its capacity.
- **Buffer Empty Handling:** Consumers wait when no chunks are available.
- **Live Dashboard:** Display buffer usage, produced chunks, consumed chunks, and waiting statistics.
- **Activity Log:** Monitor events during the simulation.
- **Streaming Controls:** Start and stop the simulation and clear the activity log.

## 🧠 Operating System Concepts

| Concept | Application in StreamFlow |
| Producer–Consumer Problem | The server produces chunks, and user devices consume them. |
| Multithreading | Producer and consumer operations run in separate threads. |
| Shared Memory Concept | Threads access a common buffer within the application. |
| Synchronization | Controls concurrent access to the buffer. |
| Mutual Exclusion | Synchronized methods prevent simultaneous execution of protected buffer operations. |
| Inter-thread Communication | `wait()` and `notifyAll()` coordinate producer and consumer threads. |
| Bounded Buffer | The buffer has a fixed maximum capacity. |
| FIFO Queue | Chunks are retrieved in the order in which they are inserted. |

## ⚙️ How It Works

1. The user enters the buffer capacity, total number of chunks, production delay, playback delay, media type, and number of user devices.
2. The streaming server starts producing media chunks.
3. The generated chunks are inserted into the shared buffer.
4. User devices retrieve chunks from the buffer in FIFO order.
5. If the buffer is full, the producer waits until space becomes available.
6. If the buffer is empty, the consumer waits until a chunk is produced.
7. Synchronization mechanisms coordinate access to the buffer.
8. The dashboard displays updated statistics and activity logs.
9. After production finishes, the remaining chunks are consumed and the simulation completes.

## 🧪 Example Test Case

Use the following configuration to demonstrate the buffer-full condition.

| Parameter | Value |
|---|---:|
| Buffer Capacity | 3 |
| Total Media Chunks | 15 |
| Production Delay | 100 ms |
| Playback Delay | 1000 ms |
| User Devices | 1 |
| Media Type | Video |

### Expected Behaviour

- The producer generates media chunks faster than the consumer processes them.
- The buffer becomes full.
- The producer waits until space becomes available.
- The consumer continues retrieving chunks from the buffer.
- The dashboard records producer and consumer waiting events.
- All 15 media chunks are eventually consumed if the simulation completes successfully.

In a recorded test, the application produced 15 chunks, consumed 15 chunks, recorded 12 producer waits and 1 consumer wait, and finished with an empty buffer.

*Note: Waiting counts depend on thread scheduling and execution timing, so they may differ between runs.*

## ⚠️ Limitations

- Media chunks are simulated objects; actual video or audio files are not streamed.
- The application demonstrates buffer management locally rather than over a real network.
- Multiple consumers sharing one FIFO queue distribute chunks among themselves; this does not reproduce broadcast streaming in which every device receives every chunk.
